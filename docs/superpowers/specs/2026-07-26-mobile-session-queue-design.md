# 移动端会话排队与引导指令设计

## 目标

让移动端会话在 Agent 正在执行时像 Codex 一样接受后续引导指令：指令按会话独立 FIFO 队列持久化，当前轮结束后自动执行；用户可以编辑、取消和查看队列，并能停止当前会话。

## 行为

- 空闲会话发送消息时立即启动 Agent。
- `running`、`queued`、等待审批状态下发送消息时创建排队项，不启动并行 Agent 调用。
- 每个排队项保存文本、附件引用、创建时间和稳定 ID；桌面端重启后保留。
- 当前轮正常完成时，自动取出首项并启动下一轮；失败时保留队列，不自动继续。
- 停止会话默认“停止当前轮并清空队列”；可选择“仅停止当前轮，保留队列”。停止后的保留队列需由用户显式继续执行，避免取消后的旧指令自动恢复。
- 队列项可编辑文本、替换附件、单项取消；执行中的项不允许编辑或取消。

## 边界与安全

- 队列仅用于已有会话，不能跨会话移动或重排。
- 继续执行仍复用原有 Agent 与审批链路；真正运行到命令时才请求授权。
- 附件仍存现有移动控制安全附件库，队列只保存公开附件引用。
- 原始完整思维链不记录或展示；保持现有“思考摘要”策略。

## 接口

- 会话详情增加 `queue` 与 `queuePaused`。
- `POST /sessions/:id/messages`：根据运行状态立即执行或入队。
- `POST /sessions/:id/queue/:itemId`：编辑队列项。
- `DELETE /sessions/:id/queue/:itemId`：取消队列项。
- `POST /sessions/:id/queue/resume`：恢复并调度保留队列。
- `POST /sessions/:id/cancel`：接受 `{ clearQueue: true|false }`。

## 验收

- 能顺序排队、自动执行、编辑、取消、停止清空、停止保留并手动继续。
- 运行状态/队列变更通过现有 SSE 及时反映。
- 队列重建后仍可读取并执行，且已有移动控制测试不回归。
