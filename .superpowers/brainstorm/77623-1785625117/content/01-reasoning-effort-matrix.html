思考档位调研：Codex vs GPT API vs 主流供应商

数据截至 2026-08-02，来源：OpenAI / DeepSeek / OpenRouter / Anthropic / Qwen 官方文档 + 本机 ~/.codex/models_cache.json

核心结论

不完全一样。重叠档（low/medium/high/xhigh）是同一字段、同一取值；但 Codex 目录与 GPT-5.6 API 全集不对齐，且 Codex 另有 ultra（编排）/ API 另有 none、pro mode。

推荐做法

逻辑档位全集 + 每模型能力表 + 出站映射；可视化同时显示「请求档 → 上游档」。

1. OpenAI / GPT-5.6

面字段支持档备注
Responses API（官方文档） reasoning.effort none, low, medium, high, xhigh, max 默认常为 medium；另有独立 reasoning.mode: pro
Chat Completions reasoning_effort 同上（model-dependent）；部分路径 max 可能 400 推荐仍用 Responses
Codex CLI 配置 model_reasoning_effort 按模型目录 出站仍变成 Responses 的 reasoning.effort
本机 Switchyard 写入的 models_cache（gpt-5.6-*） supported_reasoning_levels low, medium, high, xhigh only 缺 none / max / ultra
上游 Codex 社区目录（较新） 同上 Sol/Terra: +max +ultra；Luna: +max ultra 偏 Codex 编排，不等于 API effort

2. 其它有名供应商（出站形态）

供应商字段形态档位 / 能力相对 OpenAI 逻辑档
DeepSeek V4 thinking.type + reasoning_effort 官方：low, high, max（默认 high）；关思考用 thinking.disabled。
兼容：medium/xhigh→high；Pro 暂可能把 low→high、xhigh→max		 有损映射：多档压成 2–3 档
OpenRouter reasoning.effort 网关层：none, minimal, low, medium, high, xhigh, max；按模型 supported_efforts 再钳 最接近 OpenAI 全集
Anthropic / Claude output_config.effort（+ thinking） 常见 low, medium, high, xhigh, max（按模型子集） 名称相近，语义是 Claude effort，不是 GPT
Qwen / DashScope enable_thinking + 可选 thinking_budget 开关 + token 预算；reasoning_effort 会被静默忽略 无多档枚举，只能近似映射
MiniMax 等 如 reasoning_split / thinking 对象 多为 on/off Switchyard 现有启发式：effort→开关

3. Codex 里选 High，和直接调 GPT-5.6 API 一样吗？

  1. 字段：一样。最终都是 Responses reasoning: { effort: "high" }（你本地日志已证实）。
  2. 取值集合：不完全一样。API 有 none/max；Codex UI/目录可能没有；Codex 可能有 ultra，API 没有同名字段（接近 multi-agent / 编排）。
  3. 默认档：可能不同。API 文档默认常 medium；你本机 cache 里若干 gpt-5.6 默认是 low。
  4. Pro：API 用 reasoning.mode: "pro"；Codex 未必暴露，和 effort 正交。
